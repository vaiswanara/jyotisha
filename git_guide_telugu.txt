============================================================
           GIT VERSION CONTROL & VERSIONING GUIDE (తెలుగు)
============================================================

ఈ ఫైల్ లో గిట్ బేసిక్ కమాండ్స్ మరియు నీ ప్రాజెక్ట్ కి వెర్షన్ నంబర్స్ (ఉదా: v1.0.0) ఎలా ఉపయోగించాలో వివరించబడింది.

------------------------------------------------------------
భాగం 1: గిట్ బేసిక్ ఫ్లో (Daily Git Commands)
------------------------------------------------------------

స్టెప్ 1: ప్రస్తుతం మారిన ఫైళ్లను చూడటం (Check Status)
--------------------------------------------------
కమాండ్:
git status
(గమనిక: కొత్తగా మారిన ఫైళ్లు ఎరుపు రంగులో కనిపిస్తాయి.)

స్టెప్ 2: ఫైళ్లను సేవ్ చేయడానికి సిద్ధం చేయడం (Stage Changes)
--------------------------------------------------
అన్ని ఫైళ్లను ఒకేసారి సిద్ధం చేయడానికి:
git add .

(లేదా ఒక నిర్దిష్ట ఫైల్ ని మాత్రమే: git add folder/filename.jsx)

స్టెప్ 3: సేవ్ పాయింట్ సృష్టించడం (Commit Changes)
--------------------------------------------------
నువ్వు చేసిన మార్పుల గురించి ఒక చిన్న సందేశం రాస్తూ శాశ్వతంగా సేవ్ చేయడానికి:
git commit -m "మార్పుల వివరాలు ఇక్కడ రాయ్"

ఉదాహరణ:
git commit -m "D1 chart degrees option feature added"

స్టెప్ 4: చరిత్ర చూడటం (Check History)
--------------------------------------------------
ఇప్పటివరకు నువ్వు చేసిన అన్ని కమీట్ల చరిత్రను చూడటానికి:
git log --oneline

స్టెప్ 5: ఏదైనా తప్పు జరిగితే పాత కోడ్ కి తిరిగి వెళ్ళడం (Undo changes)
--------------------------------------------------
చివరిగా సేవ్ చేసిన కోడ్ కి రీసెట్ చేయడానికి:
git restore .

------------------------------------------------------------
భాగం 2: వెర్షన్ నంబరింగ్ (Semantic Versioning - SemVer)
------------------------------------------------------------
ప్రాజెక్ట్ కి వెర్షన్ నంబర్స్ సాధారణంగా MAJOR.MINOR.PATCH రూపంలో ఉంటాయి (ఉదా: v1.0.0).

1. MAJOR (మొదటి అంకె - v1.0.0): పెద్ద మార్పులు లేదా పాత కోడ్ పని చేయకుండా కొత్త డిజైన్ తెచ్చినప్పుడు.
2. MINOR (రెండవ అంకె - v1.1.0): కోడ్‌కు కొత్త ఫీచర్లు (Features) జోడించినప్పుడు (ఉదా: డిగ్రీల ఆప్షన్).
3. PATCH (మూడవ అంకె - v1.1.1): కేవలం చిన్న బగ్‌లు లేదా తప్పులను సరిచేసినప్పుడు (Bug Fixes).

------------------------------------------------------------
భాగం 3: గిట్ ట్యాగ్స్ ఉపయోగించడం (Git Tags for Versions)
------------------------------------------------------------
గిట్ లో ఒక నిర్దిష్ట కమీట్ కి వెర్షన్ నంబర్ ట్యాగ్ అంటించడం వల్ల, ఆ వెర్షన్ కోడ్ ఎప్పటికీ భద్రంగా ఉంటుంది.

1. కొత్త వెర్షన్ ట్యాగ్ సృష్టించడానికి:
----------------------------------------
కమాండ్:
git tag -a v1.0.0 -m "రిలీజ్ వెర్షన్ 1.0.0"

2. ట్యాగ్ చేసిన వెర్షన్ల లిస్ట్ చూడటానికి:
----------------------------------------
కమాండ్:
git tag

3. పాత వెర్షన్ కోడ్ లోకి వెళ్ళడానికి (Time Travel):
----------------------------------------
కమాండ్:
git checkout v1.0.0
(ఇది రన్ చేయగానే ప్రాజెక్ట్ మొత్తం ఆ వెర్షన్ స్థితికి మారిపోతుంది.)

4. మళ్ళీ ప్రస్తుత తాజా కోడ్ కి తిరిగి రావడానికి:
----------------------------------------
కమాండ్:
git checkout master
